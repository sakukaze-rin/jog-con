# 首次联调

1. `sh scripts/build-app.sh`，打开 `build/Jog-con.app`，保持运行。
2. 确认连接区域显示 Joy-Con (L) 和虚拟 MIDI 已就绪。输出默认关闭。
3. Premiere Pro 菜单 → 首选项 → 操纵面板 → 添加 → Mackie Control。
4. 输入端口选 `Jog-con Input`；输出端口选 `Jog-con Output`。按当前版本的对话框确认保存。
5. Jog-con 中移动实体摇杆，选择会变化的输入控件和 X/Y 轴。默认死区 12%。
6. 逐个按方向键，观察当前输入名称，为四个面板配置绑定。按钮映射默认为空，避免猜错单 Joy-Con 方向。
7. 启用输出，把 Premiere 放在前台，摇杆回中，然后轻推。记录前后时间码、方向、速度与音频擦洗表现。
8. 绑定播放、停止并验证。面板快捷键另需在 macOS 辅助功能设置中授权 Jog-con；使用 Adobe 默认 Shift+1/2/3/4，若自定义过请先核对。
9. 验证回中停止发送、切到其他 App 停止发送、断连后关闭输出、重新启用后必须回中。已开始的 Premiere 播放需显式停止。

`build/Jog-con.app/Contents/MacOS/JogCon --diagnose` 输出设备控件清单和虚拟 MIDI 回环结果。诊断会发送两条 Jog 消息；请在 Premiere 尚未绑定端口时运行。

## 当前验证边界

### 自动短推 / 长推

退出旧版，重新构建并打开 App，无需选择模式。默认单步幅度 45%、长推幅度 85%、等待 300 ms、死区 12%。在暂停时间线测试：

1. 回中后快速推过 45% 并松手：等待期间无输出，回中时 MIDI 计数增加 1，核对时间码增减 1 帧。
2. 推过 85% 并保持超过 300 ms：开始连续 Jog；松手停止且不额外补一步。
3. 等待过程中降到 85% 以下或换方向：连续等待计时重新开始。连续开始后可减小幅度调速。
4. 短推尚未松手时切出 Premiere 或关闭输出：取消短推，不在恢复时补发。
5. 无声时检查 Premiere 首选项 → 音频 → 擦洗时播放音频。比较鼠标拖动播放头、MIDI Jog、MCU Play 的声音表现；记录结果，不能把开关开启视为 MIDI 声音兼容性已验证。

- 核心自动化测试覆盖死区、曲线、相对 MIDI 编码、积分、回中与暂停恢复。
- MIDI 回环验证端口的实际字节传递，不等于 Premiere 接受协议。
- 尚需用户实际操作手柄完成 Premiere 端到端验证；不承诺无级变速播放。
- 原始 Joy-Con (L) 没有 USB-C 接口；本项目使用已配对蓝牙设备。无需 BetterJoy 或 loopMIDI。

## 有声长推联调

### 重启连接与键盘事件修正

端口现固定使用 CoreMIDI Unique ID（输入 0x4A430101、输出 0x4A430102），启动时回读验证；ID 冲突会报错而非悄悄换 ID。旧版使用系统临时 ID，升级后需要重新绑定一次。此后测试仅重启 Jog-con 是否仍可连接；若 Premiere 不自动恢复，先尝试重启 Premiere，记录为宿主热重连问题。

J/K/L 改为系统 HID 事件队列：按下保持 40 ms，再释放，按键间隔 40 ms；停止会清空旧队列，避免 K 和 L 同时到达或松手后迟到的播放命令。UI 显示实际辅助功能授权状态、已投递按键数和最近投递结果。「已投递」不是 Premiere 已执行的确认。

新版构建后如果系统显示未授权，在辅助功能列表中移除旧 Jog-con 并添加当前 build/Jog-con.app，再重开 App。此操作需由用户完成。长推测试请记录：是否显示已授权、按键计数有无增加、最近投递的是 J/L 还是 K。

用户已报告：鼠标擦洗有声，J/K 键操作有声，MIDI Jog 无声，音频首选项的擦洗音频已开启。由此新增键盘播放路径，尚待实机验收。

1. 退出旧版后打开新 App，默认勾选「有声长推」。
2. 点击授权按钮，在 macOS 隐私与安全性 → 辅助功能中手动允许 Jog-con；需要时重启 App。不需要输入监控权限。
3. 使用 Premiere 默认 J/K/L 快捷键，将焦点置于时间线，回中后短推，确认仍只走一步。
4. 长推超过阈值，确认 1× 正放/倒放有声，持续两秒不加速，松手停止且不补一步。
5. 验证反向、关闭输出、手柄断连、切换到其他 App、正常退出均停止本工具启动的播放。切出时只用 MCU Stop，不向其他 App 键入 K。
6. 修改过快捷键或键盘布局、文本框仍有焦点时需先恢复默认和时间线焦点。声音路径在此版本固定 1×，不是无级变速。

## 自动加速、短推回归与映射验收

1. 在时间线回中，快速短推，确认只走 1 帧；连续短推三次应走 3 帧。键盘可用时不依赖 MIDI 单步解释。
2. 有声长推保持到底：第 1 档启动，按加速间隔进入第 2～4 档；确认实际声音和速度，回中停止、反方向从第 1 档开始。离开长推幅度会暂停加速计时，保持现有档位。
3. 关闭有声长推，回中后长推：MIDI 计数持续增加，时间线移动；若计数增加但不动，记录端口状态，检查 Premiere 固定 ID 绑定及热重连；不能将自动化路由测试视为宿主连接已验证。
4. 旧六项绑定应保留。添加一条映射，学习实体按钮，选「下一帧」；重新启用后在 Premiere 测试按一次只触发一次。
5. 添加自定义组合并录制（例如 Shift+Command+K），确认显示修饰符，重启后组合和按钮仍保留；在 Premiere 按对应实体键核对。录制仅捕获 Jog-con 前台本地事件。
6. 分别测试预设面板、MCU Play/Stop、重复绑定提示、取消学习、删除行；不支持自动枚举 Premiere 所有内部按钮。

自动化涵盖短推/长推时序、有声关闭路由、加速上限/反向、映射持久化和旧版迁移；GUI 和 Premiere 运行时行为需用户验证。

## 连续保持与摇杆按压回归

- 修正：100 ms 以上、1 秒以内的主线程轮询延迟不再清空手势。该次不补发累计 MIDI、不增加长推等待计时；下一次正常轮询继续。超过 1 秒仍停止并要求回中，避免休眠后沿用旧手势。
- 自动化反复模拟 250 ms 延迟，覆盖正反方向、有声传输状态保持、MIDI 恢复、松手停止及短推。
- 实机：有声长推开/关各测一次，保持到底至少 30 秒，反向重复；使用足够长的序列并避免到达边界。确认松手停止、随后短推仍只走一帧。
- 按钮选择新增「按下摇杆（L3）」，兼容通用 Thumbstick Button、Left Thumbstick Button 和 extendedGamepad 别名。仅在系统实际报告输入时显示；未报告时显示提示，不创建无效按钮。学习时优先选择有中文名称的摇杆按压项。
- 实机：添加映射，学习并垂直按下摇杆，指定播放/暂停或自定义快捷键。重新启用输出，在 Premiere 按一次确认只触发一次，并核对重启后绑定保留。

## 快速连按与调度延迟

2026-11-15：确认旧键盘队列每条占用至少 40 ms 按下 + 40 ms 间隔，且释放与下一条发送均在主线程调度。输入、SwiftUI 高频发布和输出共用主线程，存在额外等待可能；这不是实测蓝牙或 Premiere 延迟的结论。

改动：
- 独立 userInteractive 串行队列发送键盘事件，保留 40 ms 按下，间隔降至 8 ms。每次按键仍按顺序完整释放，不合并播放/暂停切换。
- 输入值变化时直接处理，120 Hz 计时器保留用于持续 Jog；轴值、计数和诊断最多 30 Hz 发布，不重复发布相同状态。
- 启用期间申请 userInitiated 活动，关闭时释放，降低后台 App Nap 干扰可能；不阻止系统正常休眠。
- 新增键盘队列深度、最近/峰值等待、释放超时、输入处理间隔峰值。队列统计仅覆盖入队到系统事件投递，不包括蓝牙传输、Premiere 接收/解码/显示；轮询峰值也不是蓝牙往返延迟。队列峰值本次进程累计，轮询峰值重新启用时清零。
- 自动化使用实际串行队列验证快速连按按下/释放顺序、调用线程阻塞时继续发送、取消排队仍释放正在按下的键、目标不可用不计入成功投递。

实机对照（未由自动化代替）：
1. 同一序列分别用物理空格键与绑定到空格的 Joy-Con 按钮，按约 100–200 ms 间隔双击及连续按五次。先在摇杆回中时测试，再在长推期间测试；勿将长推的刻意等待阈值算作按钮延迟。
2. 延迟出现后查看诊断：排队持续增加/等待升高说明应用键盘路径仍有积压；释放超时升高说明发送调度或系统调用有延迟；轮询峰值升高说明输入/UI 主线程有延迟。
3. 统计低但 Premiere 响应晚只能说明这些已测代码段没有明显积压，仍可能是蓝牙输入、系统事件传递、Premiere 播放/素材处理；不能单凭统计把责任归于某一端。
4. 有声长推最高档稳定后不再重复发送 J/L。若此时画面卡顿而按键计数不变，优先做物理键盘相同倍速播放对照。关闭有声长推时仍是 MIDI 连续消息，单独测试并记录当前脉冲上限。
